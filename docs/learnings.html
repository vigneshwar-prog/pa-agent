Why RAG instead of just prompting an LLM with all documents?

LLMs have a context window limit. Even within the limit, they suffer from the "lost in the middle" problem — accuracy drops for facts buried in a long context. RAG solves this by finding only the relevant chunks and giving those to the LLM, not the whole document.

The flow: Question → embed → similarity search → top-k chunks → LLM → answer

Core architecture decisions (Mode A — 100% free/local)

LLMOllama + llama3.1:8b — runs locally, no API key, no cost. 8b is the sweet spot: fast enough on CPU, smart enough for RAG.
EmbeddingsBAAI/bge-large-en-v1.5 — 1024-dim, top MTEB score among open models. Free, local, no API key. Requires normalize_embeddings=True.
Vector DBPinecone (free tier) — managed, serverless, native metadata filtering, namespaces. Industry-standard on resumes.
FrameworkLangChain LCEL — explicit data flow, swap any component via env vars, huge ecosystem.

Do we need LangGraph for this project?

Answer: No. LangGraph is for agentic workflows — loops, branching, tool decisions, multi-agent coordination. Our pipeline is linear: retrieve → format → generate. RunnableWithMessageHistory handles multi-turn memory without any graph. LangGraph becomes relevant only if you add "should I search again?" loops or multiple specialized agents.

2026-07-29

Why Python 3.12 + venv?

The entire AI/ML ecosystem (LangChain, HuggingFace, Pinecone, FAISS) is Python-first. Node.js equivalents are poorly maintained ports. Python 3.12 adds ~5% perf over 3.11 and supports native dict[str, str] type hints without imports.

venv over conda/poetry: built-in, zero install, universally understood. Conda manages system packages (overkill). Poetry is for publishing packages (not needed for an application).

2026-07-29

Why RecursiveCharacterTextSplitter with chunk_size=600, overlap=100?

Why chunk at all? Embedding a 50,000-word document as one vector loses all specificity — "Python skills" would be buried and unretrievable.

Why Recursive over Character/Token splitters? Tries separators in order: \n\n → \n → . → . Preserves semantic units (paragraphs → sentences) instead of splitting mechanically.

Why 600 tokens? Too small (100-200) = too little context per chunk, LLM can't answer fully. Too large (1000+) = chunks cover multiple topics, retrieval gets noisy. 600 ≈ 3-5 paragraphs — specific enough to retrieve, rich enough to answer.

Why overlap=100? Prevents key sentences from being split at chunk boundaries. End of chunk N is repeated at start of chunk N+1 — no information lost.

Why tiktoken cl100k_base for length? LangChain defaults to character count. LLMs think in tokens. "tokenization" = 14 chars but only 4 tokens. tiktoken gives accurate token counts.

2026-07-29

Why SHA-256 dedup via ingestion_log.json?

During development you'll run ingest many times. Without dedup, Pinecone fills with duplicate chunks → LLM sees the same text repeated → confused, noisy answers.

Alternative: query Pinecone to check if a vector exists. Problem: costs API calls, slower. SHA-256 hash of chunk content stored in a local JSON file is instant and free. Same content always produces the same hash (deterministic), and two different texts never collide in practice.

2026-07-29

Why keyword-based category tagging (not LLM classification)?

Each chunk gets a category metadata field: skills / experience / education / personality / goals / hobbies / general. This enables filtered search (e.g. only search category=skills chunks when asked about skills).

Why not LLM classification? Ingest runs once. An LLM call per chunk makes ingest 10-20× slower. Personal documents are structured enough that keyword matching is accurate. Fast, free, zero latency.

2026-07-29

Why BAAI/bge-large-en-v1.5 and why normalize_embeddings=True?

BGE = Beijing Academy of AI. Consistently top-ranked on the MTEB (Massive Text Embedding Benchmark) leaderboard among open-source models. 1024 dimensions vs bge-small's 384 — richer vector space, better at subtle semantic distinctions ("Python developer" vs unrelated uses of the word).

normalize_embeddings=True is critical. BGE was trained with cosine similarity as the distance metric. Cosine similarity requires all vectors to be on the unit sphere (magnitude = 1). Without normalization, you're computing the wrong distance → wrong retrieval results. This is a BGE-specific requirement.

2026-07-29

Why MMR retrieval over plain similarity search?

Problem with plain top-k: If a topic appears multiple times in your docs (common in ChatGPT exports), plain similarity returns near-identical chunks — wasting 3 of your 6 context slots on duplicates.

MMR (Maximum Marginal Relevance) selects the next chunk based on: λ × relevance_to_query − (1−λ) × similarity_to_already_selected

lambda_mult=0.7 = 70% relevance, 30% diversity. From fetch_k=20 candidates, you get 6 chunks covering different aspects. Better context → better answers.

2026-07-29

Why temperature=0.3 for the LLM?

Temperature controls randomness (0 = deterministic, 1 = creative). For a personal knowledge base you want factual accuracy, not creativity. 0.3 is low enough to keep answers grounded in the retrieved context, but not 0 (which causes robotic, repetitive phrasing). If this were a creative writing assistant, you'd use 0.7-0.9.

2026-07-29

Why LangChain over raw API calls or LlamaIndex?

vs raw API calls: Without LangChain you manually write: embed the query, call the vector DB, format the prompt, inject history, parse the output, handle streaming. LangChain gives you composable building blocks. You focus on RAG logic, not plumbing.

vs LlamaIndex: LlamaIndex is excellent but opinionated — works perfectly when you follow its patterns, gets painful when you customize. LangChain LCEL (the | pipe operator) gives explicit control over every step — better for learning because you can see the data flow at every stage.

❓ Questions Asked & Explored
2026-07-29

Which production embedding model should I use for learning?

Recommendation: Pinecone for vector DB (industry-standard, free tier). For embeddings, stick with bge-large locally — it's free and competitive. For the LLM, OpenAI GPT-4o-mini is the production standard if you want paid experience ($5 free credit on signup).

Swapping any component in this project is just an env var change — the LangChain abstraction means zero code changes when moving from Ollama to OpenAI.

⚡ Gotchas & Surprises
2026-07-29

bge models REQUIRE normalize_embeddings=True

Forgetting this flag produces incorrect cosine similarity scores. Retrieval will return wrong chunks — the bug is silent (no error, just bad answers). Always set encode_kwargs={"normalize_embeddings": True} when using any BGE model.

2026-07-29

LangChain defaults to character count for chunk size, not tokens

Without passing a custom length_function, RecursiveCharacterTextSplitter(chunk_size=600) means 600 characters — roughly 150 tokens. Always pass length_function=lambda t: len(tiktoken.get_encoding("cl100k_base").encode(t)) for accurate token-based chunking.
